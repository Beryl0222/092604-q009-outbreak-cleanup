# 聚集性胃肠事件清消

本项目提供聚集性胃肠事件清消的服务端能力：值班台接到电话、门店工单、物业记录等多渠道呕吐腹泻线索后，按共同就餐、发生时段和场所分区聚合为事件，再依据已登记规则推进污染物清理、消毒作用、复开检查与食品处理人员返岗。

## 能力

- **线索聚合**：`report_clue` 按场所分区、发生时段窗口和共同就餐（就餐批次）把电话 / 工单 / 物业线索聚合到同一事件，每条线索的来源保留；不同就餐批次不被过早合并，而是列为尚待核查并记为事实冲突。本服务不作医学诊断，携带诊断字段的线索会被拒绝。
- **处置规则**：`register_rule` 登记带有效期的规则（方案步骤、关键步骤、允许的消毒剂、作用时长、复查间隔、返岗合格角色）。酒精擦拭不能认作满足诺如病毒清消要求，无论登记规则还是执行消毒步骤都会被拒绝。
- **处置方案**：`start_plan` 按当前适用规则生成方案；`begin_step` / `complete_step` 执行步骤，消毒步骤强制校验作用时长。
- **复开检查**：`inspect_zone` 在事实冲突未解决、关键步骤跳过、作用时间不足或方案过期时保持区域关闭；全部满足且检查通过方可复开。`verify_batch` / `resolve_conflict` 用于核查批次与解决冲突。
- **返岗决定**：`decide_return` 要求由独立于门店经理的合格角色（规则中登记）作出。
- **模拟时钟**：`advance_clock` 由值班人员推进，复查逾期的关闭区域逐级升级；计时依据持久化在存储中，重启服务后不会重置。`recheck_zone` 登记复查并顺延期限。
- **区域视图**：`view_zone` 返回区域状态、关闭或复开理由、尚待核查的就餐批次、当时适用的处置规则、未解决冲突、复查与升级记录及当前复开阻断原因。

## 目录

- `src/clock.js` 可替换时钟与持久化的模拟时钟。
- `src/store.js` 进程内记录与元数据存储。
- `src/service.js` 线索聚合、规则、方案、复开、返岗与升级的领域逻辑。
- `src/api.js` 处理进程内 JSON 请求。
- `src/cli.js` 提供标准输入入口。
- `test/` 覆盖当前已有行为。

## 运行

运行测试：`npm test`

检查构建：`npm run build`

本地冒烟：`printf '%s' '{"action":"health"}' | npm run cli --silent`

项目只使用 Node.js 内置能力，运行期间不连接其他服务。
